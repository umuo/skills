# Solo 博客文章写作与封面规范

本文档定义通过 `solo-admin` 撰写、配图、标注生成来源与发布 Solo 博客文章的统一风格标准。

---

## 1. 顶部封面图规范（优先调用生图，无能力则跳过）

发文章前，优先基于**整篇文章的主题与核心内容**生成 1 张封面图，并将其放置在正文最顶部充当文章封面。若生图能力或图床不可用，省略封面图并继续检查发布条件。

### 1.1 生图时机与主题提炼

- 在文章正文成稿或核心大纲已确定后，提炼一个能概括全文的短标题，以及 3～5 个适合画成图解的要点。
- 默认采用横版 **`16:9`**（推荐 `1280×720`，与 Solo 默认首图尺寸一致），需要超宽构图时可采用 **`2.35:1`**。

### 1.2 生图能力探测优先级

按以下顺序检查当前 Agent 是否具备可用的生图能力：

1. **已安装的封面/生图专项技能**：如 `baoyu-cover-image`、`imagegen` 等。
2. **宿主内置生图子代理或工具**：如 `image-generator` 子代理、MCP 生图工具、多模态图像生成接口等。
3. **无生图能力时**：如果以上工具均不可用，**不要**编造图片链接、**不要**自行从外部网站盗链、也**不要**擅自调用 `/console/thumbs` 塞入与主题无关的随机图——直接跳过生图，进入纯文本/代码发布流程。

使用专项技能或生图工具时，将下节模板填好后作为最终生图提示词，优先选支持自定义提示词的工具。

### 1.3 手绘技术信息图提示词

默认使用白纸底、粗笔手写标题、彩色分区的中文手绘信息图。根据文章内容确定各区块的短标签和关系，再替换模板中的占位内容。流程用箭头连接，对比用小表格，层级用框图，容易踩坑的地方可加便签。若用户提供参考图，用它约束笔触、配色和版式，图中文字和技术内容取自当前文章。

```text
为博客文章绘制一张横版中文手绘信息图封面，画幅为【画幅比例】。

在画面顶部用醒目的黑色粗笔手写「【封面短标题】」，用蓝色和黄色的手绘波浪线划出标题重点。背景是明亮的白纸，线条像黑色签字笔，略有手绘起伏，局部用彩铅或马克笔排线轻涂。

标题下方用错落但对齐的手绘框线组织以下内容，让最重要的图解占据最大的区块。
【填入 3～5 个区块的简短标题、图解类型、图中标签，以及需要表达的顺序或对比关系】

用蓝、绿、紫、橙红区分区块，搭配彩色手绘标题条。用与主题相关的小图标、箭头和手绘表格讲清要点。边角可以画一只小小的卡通猫，拿与主题相关的道具作点缀。画面信息丰富，区块之间和四周留出空隙，让标题和主要图形在博客缩略图里依然容易辨认。

只绘制提供的主标题、区块名和少量关键词。简体中文写清楚，英文技术名词按给定拼写绘制。把文章里的细节压缩成图形和短标签，避免长段落、过小文字和未经文章证实的数据或结论。
```

### 1.4 转为公网 HTTPS 链接（关键约束）

Solo 服务端保存或更新文章时，会解析正文与摘要中的**第一张图片 `<img src="...">`** 写入数据库字段 `articleImg1URL`（`VARCHAR(255)`），作为文章列表卡片与分享首图。因此必须满足：

- **严禁使用本地路径或 Base64**：不得将 `/tmp/cover.png`、`./cover.png` 或 `data:image/png;base64,...` 直接写入 `articleContent`（本地路径线上无法访问，Base64 会超出 `articleImg1URL` 255 字符上限导致保存失败）。
- **本地生图后上传获取 URL**：
  ```bash
  python3 "<skill-dir>/scripts/solo_api.py" --upload "/path/to/cover.png"
  ```
  该命令会自动向 Solo 后台获取上传凭证并上传至社区图床，返回可用的 `https://...` 短链接（校验 `<= 255` 字符）。
- **临时外链转存**：若生图工具直接返回了一个有效期较短的公网临时 URL，可调用转存命令将其持久化到社区图床：
  ```bash
  python3 "<skill-dir>/scripts/solo_api.py" --upload-url "https://example.com/temp-cover.png"
  ```

### 1.5 封面放置位置与降级规则

- **放置位置**：将封面 Markdown 放在 `articleContent` 的**第 1 行**，后留一个空行，接生成署名或开篇正文。完整排版见下节。
- **优雅降级**：若无生图能力、生图调用失败，或 Solo 社区图床无法提供公网 HTTPS 链接（如 `--upload` 返回退出码 `5`），省略封面图，并在最终回复中说明“已跳过封面图生成/上传”。

### 1.6 文章生成署名（发布前必检）

由 AI 生成主体内容的文章，在创建并发布或将草稿转为发布前，必须在 `articleContent` 顶部加入一个 Markdown 引用块。固定使用「生成工具」和「生成模型」两个字段，工具在上，模型在下，使用全角冒号。两行均以 `>` 开头，在第一行末尾加反斜杠，让两个字段各占一行。无法确认工具时省略整行「生成工具」，只保留「生成模型」。工具名称使用官方写法，如 `Codex`、`Antigravity`。模型名称使用生成正文时运行环境明确提供或用户确认的名称。

有封面时，署名放在封面之后，与封面、正文各隔一个空行。无封面时，署名放在第一行，后空一行再写正文。

```markdown
![文章封面](https://example.com/cover.png)

> **生成工具**：Codex\
> **生成模型**：gpt-6.2-sol

这里是开篇导语……

## 一、问题背景
```

- 发布前检查署名的位置、格式和实际模型名称。模型无法确认时，暂停发布，请用户提供生成正文的模型名称。草稿可以先准备，正式发布前须补齐署名。
- 原样代发的内容沿用其已确认的来源。修改已发布文章的标题、标签或局部正文时，保留原署名。生成署名只出现一次，放在正文顶部。

## 2. 标题、摘要与标签规范

- **`articleTitle`（标题）**：准确概括核心问题、方案或结论，言之有物，避免空洞标题党。
- **正文禁止重复一级标题**：Solo 主题模板会自动将 `articleTitle` 渲染为页面主标题 `<h1>`。`articleContent` 中的章节标题统一从 **`##`（二级标题）** 开始，不要在第一行再写 `# 文章标题`。
- **`articleAbstract`（摘要）**：撰写 80～160 字精炼导读，点明解决什么问题、采用什么核心思路或得到什么结论。摘要内省略封面图、生成署名和大段代码块，方便列表页直接展示导读。
- **`articleTags`（标签）**：
  1. 发布前先调用 `GET /console/tags` 检查博客现有标签，**优先复用已有命名**（注意大小写一致），避免同义碎片化标签。
  2. 每篇文章建议配置 **2～4 个** 标签，使用英文逗号分隔（Solo 最多保留 4 个标签，留空会自动设为 `"待分类"`）。

---

## 3. 行文风格与叙事结构

- **语言基调**：中文表述自然、平实、重实据；避免“总而言之”“综上所述”“赋能”“抓手”“不仅如此，而且……”等 AI 八股腔。
- **技术名词保留原名**：代码符号、类名/方法名、HTTP 状态码、配置项、CLI 命令与协议字段保留英文原文并使用反引号包裹（如 `X-Solo-API-Key`、`HTTP 401`、`PUT /console/article/`）。
- **推荐技术文章脉络**：
  1. **场景 / 问题引入**：遇到了什么具体问题或痛点、触发条件是什么；
  2. **原理剖析或方案取舍**：核心机制、源码/协议链路、各方案优劣对比；
  3. **可运行实现 / 操作步骤**：给出完整且自洽的代码、配置或命令行；
  4. **踩坑要点与验证总结**：边界条件、易错点、验证方式与实际结果。

---

## 4. Solo Markdown 兼容与发布前脱敏

- **代码块声明语言**：所有围栏代码块必须显式标明语言标识（如 `bash`、`java`、`python`、`json`、`yaml`、`sql`）。
- **勿用 GitHub 专属 Callout 语法**：Solo 使用 Lute / Flexmark 渲染 Markdown，不支持 GitHub 的 `> [!NOTE]`、`> [!WARNING]`、`> [!CAUTION]` 语法，直接写会原样露出 `[!NOTE]`。需要强调提示时，统一使用标准引用加粗写法：
  ```markdown
  > **注意**：这里写提示内容。
  ```
- **发布前隐私与脱敏检查**：正文、代码片段、命令行示例与配置样例中**严禁**出现真实 `sk-...` API Key、数据库密码、个人邮箱/手机号、本机用户路径（如真实 `/Users/<name>/...`）或未公开的内网/公网服务地址；统一以占位符替代（如 `<skill-dir>`、`<your-api-key>`、`https://example.com`）。
