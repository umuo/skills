# Solo 博客文章写作与封面规范

本文档定义通过 `solo-admin` 撰写、配图与发布 Solo 博客文章的统一风格标准。

---

## 1. 顶部封面图规范（优先调用生图，无能力则跳过）

发文章前，优先基于**整篇文章的主题与核心内容**生成 1 张封面图，并将其放置在正文最顶部充当文章封面；若当前运行环境不具备生图能力（或图床不可用），则直接省略封面图，正常完成文章发布，切勿阻塞流程。

### 1.1 生图时机与主题提炼

- 在文章正文成稿或核心大纲已确定后，从全文视角提炼主视觉意象（不要只截取某一段细节）。
- 推荐横版宽屏比例：**`16:9`**（推荐像素 `1280×720`，与 Solo 默认首图尺寸 `ARTICLE_THUMB_IMG_WIDTH × ARTICLE_THUMB_IMG_HEIGHT` 一致）或 **`2.35:1`**。

### 1.2 生图能力探测优先级

按以下顺序检查当前 Agent 是否具备可用的生图能力：

1. **已安装的封面/生图专项技能**：如 `baoyu-cover-image`、`imagegen` 等。
2. **宿主内置生图子代理或工具**：如 `image-generator` 子代理、MCP 生图工具、多模态图像生成接口等。
3. **无生图能力时**：如果以上工具均不可用，**不要**编造图片链接、**不要**自行从外部网站盗链、也**不要**擅自调用 `/console/thumbs` 塞入与主题无关的随机图——直接跳过生图，进入纯文本/代码发布流程。

### 1.3 视觉风格与构图建议

根据文章类型选择契合的视觉风格：

| 文章类型 | 推荐视觉风格 | 画面要点 |
| --- | --- | --- |
| 架构设计、源码剖析、故障排查 | 技术蓝图（blueprint）、等距结构图、深色氛围（dark-atmospheric） | 层次清晰的模块/链路意象，冷色调或深底高亮 |
| 工具实战、开发教程、Agent 工作流 | 信息图解（editorial-infographic）、扁平矢量、手绘笔记风（sketch-notes） | 流程节点明确、留白充足、对比清爽 |
| 阶段复盘、技术随笔、经验思考 | 极简（minimal）、温暖插画（warm）、水彩风（watercolor） | 画面克制、意象简洁、情绪自然 |

- **控制画面文字**：封面尽量采用纯视觉隐喻；如需标题字样，仅保留 2～6 个词的极短主标题或英文关键词，避免密集小号中文段落导致文字畸变。

### 1.4 转为公网 HTTPS 链接（关键约束）

Solo 服务端保存或更新文章时，会解析正文与摘要中的**第一张图片 `<img src="...">`** 写入数据库字段 `articleImg1URL`（`VARCHAR(255)`），作为文章列表卡片与分享首图。因此必须满足：

- **严禁使用本地路径或 Base64**：不得将 `/tmp/cover.png`、`./cover.png` 或 `data:image/png;base64,...` 直接写入 `articleContent`（本地路径线上无法访问，Base64 会超出 `articleImg1URL` 255 字符上限导致保存失败）。
- **本地生图后上传获取 URL**：
  ```bash
  python3 "<skill-dir>/scripts/solo_api.py" --upload "/path/to/cover.png"
  ```
  该命令会自动向 Solo 后台获取上传凭证并上传至社区图床，返回可用的 `https://...` 短链接（校验 `<= 255` 字符）。
- **临时外链转存**：若生图工具直接返回了一个有效期较短的公网临时 URL，可调用转存命令将其持久化到社区图床：
  ```bash
  python3 "<skill-dir>/scripts/solo_api.py" --upload-url "https://example.com/temp-cover.png"
  ```

### 1.5 封面放置位置与降级规则

- **放置位置**：将封面 Markdown 放在 `articleContent` 的**第 1 行**，后空一行再写开篇导语或正文第一节：
  ```markdown
  ![文章封面](https://...)

  这里是开篇导语……

  ## 一、问题背景
  ```
- **优雅降级**：若无生图能力、生图调用失败、或 Solo 社区图床未配置导致无法转为公网 HTTPS 链接（如 `--upload` 返回退出码 `5`），**直接省略第 1 行封面图**，正常发布正文，并在最终回复中如实说明“已跳过封面图生成/上传”即可。

## 2. 标题、摘要与标签规范

- **`articleTitle`（标题）**：准确概括核心问题、方案或结论，言之有物，避免空洞标题党。
- **正文禁止重复一级标题**：Solo 主题模板会自动将 `articleTitle` 渲染为页面主标题 `<h1>`。`articleContent` 中的章节标题统一从 **`##`（二级标题）** 开始，不要在第一行再写 `# 文章标题`。
- **`articleAbstract`（摘要）**：撰写 80～160 字精炼导读，点明解决什么问题、采用什么核心思路或得到什么结论；摘要内**不要放图片或大段代码块**，避免列表页卡片排版错乱。
- **`articleTags`（标签）**：
  1. 发布前先调用 `GET /console/tags` 检查博客现有标签，**优先复用已有命名**（注意大小写一致），避免同义碎片化标签。
  2. 每篇文章建议配置 **2～4 个** 标签，使用英文逗号分隔（Solo 最多保留 4 个标签，留空会自动设为 `"待分类"`）。

---

## 3. 行文风格与叙事结构

- **语言基调**：中文表述自然、平实、重实据；避免“总而言之”“综上所述”“赋能”“抓手”“不仅如此，而且……”等 AI 八股腔。
- **技术名词保留原名**：代码符号、类名/方法名、HTTP 状态码、配置项、CLI 命令与协议字段保留英文原文并使用反引号包裹（如 `X-Solo-API-Key`、`HTTP 401`、`PUT /console/article/`）。
- **推荐技术文章脉络**：
  1. **场景 / 问题引入**：遇到了什么具体问题或痛点、触发条件是什么；
  2. **原理剖析或方案取舍**：核心机制、源码/协议链路、各方案优劣对比；
  3. **可运行实现 / 操作步骤**：给出完整且自洽的代码、配置或命令行；
  4. **踩坑要点与验证总结**：边界条件、易错点、验证方式与实际结果。

---

## 4. Solo Markdown 兼容与发布前脱敏

- **代码块声明语言**：所有围栏代码块必须显式标明语言标识（如 `bash`、`java`、`python`、`json`、`yaml`、`sql`）。
- **勿用 GitHub 专属 Callout 语法**：Solo 使用 Lute / Flexmark 渲染 Markdown，不支持 GitHub 的 `> [!NOTE]`、`> [!WARNING]`、`> [!CAUTION]` 语法，直接写会原样露出 `[!NOTE]`。需要强调提示时，统一使用标准引用加粗写法：
  ```markdown
  > **注意**：这里写提示内容。
  ```
- **发布前隐私与脱敏检查**：正文、代码片段、命令行示例与配置样例中**严禁**出现真实 `sk-...` API Key、数据库密码、个人邮箱/手机号、本机用户路径（如真实 `/Users/<name>/...`）或未公开的内网/公网服务地址；统一以占位符替代（如 `<skill-dir>`、`<your-api-key>`、`https://example.com`）。
