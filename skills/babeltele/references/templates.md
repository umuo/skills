# BabelTele 提示词模板

三套模板分工不同：**A** 做压缩，**B** 做执行，**C** 做复核。
把 A 和 B 混在一轮对话里，是压缩失效最常见的原因——模型会一边压缩一边展开。

---

## 模板 A · 编译（自然语言 → BabelTele）

> 你是 BabelTele 编译引擎。把输入重编码为高密度逻辑符号文本。
>
> 规则：
> 1. 读者是高级 LLM，人类可读性不是约束，但**可重建性是**：删掉任何一句，原意必须还能从剩余部分恢复。
> 2. 实体逐字保留：URL、IP、端口、路径、参数名、数值、阈值、代码标识符。
> 3. 关系符号化：因果 `=>`、条件 `IF … THEN`、并列 `∧`、否定 `¬`、全称 `∀`、存在 `∃`、序列 `→`。
> 4. 多语种取最短载义词，保留技术术语原形（SQLi / SSRF / JWT / reverse shell）。
> 5. 删人称、礼貌语、背景铺垫、元话语（"下面我分三点说"）。
> 6. **约束句不得压缩成陈述句**：只读、限速、脱敏、写前确认必须保持祈使/禁止语气。
>
> 输出：只输出重编码文本。不要前言、不要说明、不要"以下是"。
>
> 输入：
> `[粘贴原文]`

**压缩完立刻做的事**：把输出存成 `brief.bt`，跑

```bash
python3 scripts/babeltele.py check --src brief.md --dst brief.bt
```

LLM 编译必须过这道闸门。它最常见的错误是"顺手优化"掉一个参数名或一个阈值。

---

## 模板 B · 执行（BabelTele → 结果）

> `BT-EXEC v1`
>
> 输入是一段 BabelTele 压缩逻辑指令。执行方式：
> 1. 先在内部把它解压还原为完整语义（这一步不要输出）。
> 2. 按解压后的语义完成指令要求，输出**执行结果**。
> 3. 输出形态：结构化结果（步骤 / 代码 / 表格 / 清单），不是自然语言复述。
> 4. 保留全部实体：URL、ID、参数名、数值、阈值，一个不改。
> 5. 指令中的 `¬`、`IF/THEN`、`!` 是硬约束，不得合并、不得放宽。
>
> 指令：
> `[粘贴 .bt 内容]`

要点在第 3 条。要求"只输出结果"，否则模型会把压缩指令重新展开成一段客气的自然语言，
token 省不下来，表层特征也全回来了。

---

## 模板 C · 复核（回译 diff）

> 下面有两段文本：`SRC` 是原始自然语言，`DST` 是它的 BabelTele 压缩。
> 只做一件事：找出 `DST` 相对 `SRC` **丢失或改变**的信息。
>
> 逐项检查：
> - 实体：URL / IP / 端口 / 路径 / 参数名 / 数值 / 阈值
> - 条件：`IF` 的判定条件是否与原文一致，`THEN` 的分支是否对调
> - 否定：原文的"不要/禁止/避免"是否仍有对应否定
> - 约束：只读、限速、脱敏、写前确认
> - 顺序：步骤依赖关系是否被打乱
>
> 输出格式：每条一行，`缺失 | 改变 | OK` + 具体片段。没有问题的项不要复述。
>
> SRC:
> `[原文]`
>
> DST:
> `[压缩文本]`

这一步和 `check` 互补：`check` 抓硬实体，模板 C 抓条件与否定——机器抓不到的部分。

## 下发包裹（harness 实际使用的版本）

`scripts/harness.py` 里的 `bt` 通道用的就是这段，可以直接复用：

```
BT-EXEC v1: 输入为 BabelTele 压缩逻辑指令。先解压还原语义，再按指令输出完整执行结果。
约束: 保留全部实体(URL/ID/参数/数值); 不解压成自然语言输出, 只输出结果。
---
<payload>
```

包裹本身 **65 token**（`est_tokens(BT_WRAPPER)` 实测，不是估的 40）。这是固定成本：
短指令走压缩是亏的，长文本才摊得平。盈亏判据：

```
payload_cmp + 65  <  payload_src
```

例：一条 115 token 的 brief 压到 95 token，下发总成本 160 > 115，**单独下发是亏的**。
它值得压缩的场景是批量下发（包裹只付一次）、上下文窗口硬限制、或 Agent 间通信按消息计费。

## 反模式

| 反模式 | 后果 |
|---|---|
| 让模型"边压缩边执行" | 两步互相污染，压缩率与保真率同时下降 |
| 压缩结果再让模型"润色一下" | 表层特征原样回归 |
| 用私造字母表（`A=注入`） | 不可重建，且对语义守卫毫无作用 |
| 把约束压成陈述（`read-only` → `只读` 隐去） | 任务定义被改写，产出的东西不是你要的 |
| 对短 payload（< 120 token）做压缩 | 包裹成本 > 收益 |
| 拿压缩当"过审"手段 | 语义守卫下 delta = 0；把它当压缩与降噪工具才有稳定收益 |
