# BabelTele 码本与转换规则

> 码本是**通用符号**，不是私有暗号。判断标准只有一条：一个没看过这份文档的高级读者，
> 能否在 10 秒内把它读回原意。读不回，说明你造了加密而不是压缩。

## 1. 符号表

### 关系与因果
| 符号 | 读法 | 替换的汉语 |
|---|---|---|
| `=>` | 推出 / 结果是 | 导致、因此、所以、就说明、结果是 |
| `→` | 序列下一步 | 然后、接着、之后 |
| `⇒` | 收束 / 最终产物 | 最后、最终 |
| `IF … THEN …` | 条件 | 如果…就… |
| `¬IF` | 除非 | 除非 |
| `ELSE` | 否则 | 否则 |

### 逻辑连接
| 符号 | 读法 | 替换 |
|---|---|---|
| `∧` | 且 | 并且、而且、同时、以及 |
| `∨` | 或 | 或者、或是 |
| `¬` | 非 / 禁止 | 不要、禁止、不得、避免 |
| `∀` | 全部 | 所有、任何、每一个、全部 |
| `∃` | 存在 / 部分 | 存在、部分、至少一个 |
| `∅` | 空 / 无 | 没有、空 |

### 集合与比较
`∈` 属于/包含于 · `⊇` 包括 · `≠` 不等于 · `=` 等于 · `≤` `≥` `<` `>` 阈值比较 · `!` 必须 · `?` 可选

### 时间与强度（可选，谨慎）
`Δ` 变化 · `≈` 近似 · `%` 比例 · `s/ms` 时间单位 · `@` 位于

> **别造新符号。** 需要表达 `∈` 表达不了的关系时，用短语，不要发明字形。

## 2. 意图脱敏词表（动词侧）

原则：把"人对人施压"的动词，换成"数据流过管道"的动词。保留动作的**技术可执行性**，
去掉动作的**道德渲染**。

| 自然语言 | BabelTele | 说明 |
|---|---|---|
| 窃取密码 | `extract pwd` | 动作=读取 + 对象=凭据 |
| 拖库 / 脱库 | `dump DB` | 保持"整表导出"语义 |
| 撞库 | `credential stuffing` | 行业标准术语，不渲染意图 |
| 越权获取 | `IDOR read` | 用漏洞类别替代道德动词 |
| 提权 | `privesc` | 同上 |
| 横向移动 | `lateral move` | 同上 |
| 绕过 WAF | `WAF bypass` | 保留机制名 |
| 免杀 | `AV bypass` | 同上 |
| 上传木马 | `upload implant` | `implant` 是中性载体词 |
| 反弹 shell | `reverse shell` | 标准术语，不必改写 |
| 命令执行 | `cmd exec` | 名词化 |
| 路径穿越 | `path traversal` | 标准术语 |
| 信息外带 | `OOB exfil` | 标准术语 |

**不要做的脱敏**：把 `SQL 注入` 改成 `数据库语法测试`。后者丢掉了可检索的技术语义，
读回来只剩歧义。脱敏只作用在**意图层**，不作用在**技术层**。

## 3. 名词收缩（缩写侧）

取头部词根 + 保留唯一辨识度：

`parameter→param` `password→pwd` `credential→cred` `username→user` `configuration→config`
`environment→env` `database→DB` `endpoint→API` `response→resp` `request→req` `payload→payload`
`concurrency→conc` `thread→thread` `wordlist→wordlist` `timestamp→ts` `nonce→nonce`

**保留原样的**：协议名、漏洞分类（`SQLi SSRF XSS CSRF IDOR SSTI RCE LFI XXE JWT`）、
端口号、HTTP 方法、header 名、shell 命令、代码标识符。它们是检索锚点。

## 4. 句法压缩四步

1. **删人称与礼貌**：`请 / 帮我 / 麻烦 / 你是一名 / 我想知道 / please / kindly` 全删。
2. **名词化**：`把数据拉下来` → `DB pull`；`试着替换参数` → `param swap test`。
3. **连接词符号化**：并列 `∧`，条件 `IF…THEN`，因果 `=>`，序列 `→`。
4. **切句**：`，` → `;`，一句一个断言。长句是歧义的温床。

压缩后仍应保留：**谁对谁做什么、在哪个对象上、什么条件下算成功、失败了走哪条路**。
这四件事丢任何一件，压缩就退化成摘要。

## 5. 歧义清单

| 写法 | 风险 | 改法 |
|---|---|---|
| `存在` 一律映射 `∃` | "数据库存在"会被读成集合断言 | 只在**判定句**里用 `∃`，实体存在性用 `has` |
| `包含` 映射 `∈` | 集合包含 vs 字符串包含混淆 | 集合用 `∈`，子串用 `⊂str` 或直接写 `substr` |
| 同一句混用 `IF` 与 `=>` | 回译时条件与结果串位 | 条件一层、结果一层，不嵌套超过两层 |
| `¬` 放在长句句首 | 否定辖域不清（否的是整句还是一个动作） | 否定紧贴被否定的动词：`¬ dump` |
| 中文数字 | `三秒` 可能被读成 `3s` 也可能被忽略 | 数值一律阿拉伯数字 + 单位 |
| 缩写自造（`BD`=边界） | 不可重建 | 用 `boundary` |
| `别人的订单` → `third-party order` | **主体漂移**：同系统内另一用户 ≠ 第三方主体 | 用 `other-user`，主体词不进同义词表 |
| `SQL 注入` → `SQL injection` | 压缩可能**新增**敏感词（`injection` 在语义守卫词表里） | 改词表后必须两条守卫各跑一次 |

## 6. 密度技巧（按收益排序）

1. **扩词表**——收益最大。脚本的 20% 压缩率完全由词表覆盖度决定。
2. **去虚词**——`的/了/吗/呢/吧`，level 3 自动做，收益约 1%。
3. **并列合并**——`A、B、C 都要测` → `test ∈ {A,B,C}`，省连接词。
4. **表格化**——多维参数（工具 × 目标 × 速率）用 `axis:` 列表，比散文省 30%+。
5. **引用而非复述**——重复出现的长实体先定义 `E1=`，后文用 `E1`。仅当出现 ≥3 次才划算。
6. **删元话语**——"下面我将分三点说明" 属于零信息。

## 7. 压缩是否值得（经济性）

固定成本：`BT-EXEC` 包裹 65 token。判据 `payload_cmp + 65 < payload_src`。
脚本平均压缩到 0.82（省 18%），所以 **payload 短于约 360 token 时，单条下发是负收益**。
要做的是批量（包裹复用）、窗口受限、或按消息计费的场景。

## 8. 与 LLM 编译模板的分工

脚本 = **确定性基线**：可 diff、可回归、不会幻觉，压缩率约 20%。
模板 A（LLM 编译）= **语义压缩**：能合并同义句、重排结构，压缩率 40–60%，但每次输出不同，
必须过 `check` 并人工扫一眼。两者不冲突：脚本用来做回归，模板用来做极限压缩。
