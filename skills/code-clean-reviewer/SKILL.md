# 🔍 高级代码清洁与安全审查技能 (code-clean-reviewer)

本技能旨在帮助 AI Agent 在开发或提交代码前，对即将并入仓库的修改进行多维度、深度的静态代码审查（Code Review），确保代码的可读性、可维护性，同时拦截潜在的安全缺陷。

## 🎯 触发场景与激活条件
当用户发出类似以下指令时，自动激活并应用本技能的 Playbook 规则：
- *“帮我 review 一下这段代码”*
- *“看下我的修改有没有什么漏洞或 bug”*
- *“检查一下这块逻辑写得合不合理”*
- *“在提交前帮我做一下代码审计”*

---

## 📋 核心运行手册 (Playbook)

请 AI Agent 严格按照以下流程处理代码审查任务：

### 第一步：获取待审查的代码范围
1. 若用户指定了特定文件或代码片段，直接以该输入为准。
2. 若用户要求审查当前仓库的修改，执行 `git diff` 或 `git diff --cached` 提取所有变动行，确保只对“新增/修改”的代码行进行审查，避免对未修改的存量文件进行过度轰炸。

### 第二步：进行多维度的深度审查

AI Agent 应从以下三个核心维度对代码进行细致评估：

#### 🛡️ 维度一：安全防线 (Security Check)
*   **敏感信息泄露**：检查是否硬编码了 API Key、Token、密码、加密私钥或数据库连接字符串。
*   **注入风险**：检查 SQL 查询是否采用参数化方式，是否存在 SQL 注入、OS 命令注入或 HTML XSS 注入风险。
*   **权限与越权**：检查关键业务操作是否引入了用户身份和越权校验。
*   **异常处理安全**：检查异常捕获中是否向前端输出或向日志打印了敏感系统堆栈信息。

#### 🧹 维度二：清洁度与可读性 (Clean Code & Readability)
*   **命名与语义**：变量名、函数名是否清晰传达了其意图？是否有无意义的缩写？
*   **复杂度控制**：是否存在过深的 `if-else` 嵌套或循环嵌套？函数的圈复杂度（Cyclomatic Complexity）是否过高（单函数建议行数不超过 50 行）？
*   **代码重复**：是否存在明显的复制粘贴代码（DRY 原则）？是否能抽象为公用方法？
*   **死代码清理**：是否有被注释掉的废弃代码、未使用的导入（imports）或未使用的变量。

#### ⚙️ 维度三：健壮性与健壮设计 (Robustness)
*   **边界与异常处理**：是否有空指针（NullPointerException / Undefined）保护？是否有网络超时重试机制？异步 Promise 是否有 `.catch`？
*   **资源释放**：文件流、数据库连接、定时器等在使用后是否有可靠的安全关闭（如 `try-with-resources` 或 `finally` 块中释放）。

### 第三步：输出结构化的审查报告
请不要进行模糊的评价。生成一份言之有物、条理清晰的中文报告，格式如下：

> ### 📊 代码安全与清洁度审查报告
> 
> #### 🚨 严重/高危问题 (Must Fix)
> *   *如果有安全隐患或直接导致运行崩溃的 Bug，在此列出具体文件路径、行号，解释原因并提供**修复后的正确代码 diff**。*
> 
> #### 💡 优化与清洁建议 (Suggestions)
> *   *关于 Clean Code、重构或可读性提升的修改建议，附带对比示范。*
> 
> #### ✨ 亮点与肯定 (Good Practices)
> *   *肯定代码中写得精妙、结构良好或安全性处理到位的地方，给予正面反馈。*
